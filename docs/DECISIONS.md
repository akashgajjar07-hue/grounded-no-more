# Decision log

Every non-obvious choice, with the reasoning behind it. Newest last.

| # | Date | Decision | Why |
|---|---|---|---|
| D001 | 2026-11-26 | Python package `gnm` uses a `src/` layout. The data contract lives at `src/gnm/schemas.py` rather than `src/schemas.py`. | Importable, testable package. The brief's `src/schemas.py` intent is kept: one schema module is the source of truth. |
| D002 | 2026-11-26 | Policies are **parameter tables** (`PolicySpec`) run by **one** policy-agnostic event engine. | Paired comparisons need identical mechanics. Policy differences then come only from parameters and network rules, never from different code paths. |
| D003 | 2026-11-26 | Exogenous demand (flights, removals, kits, line usage) and common random numbers (repair durations, condemnation flags, lead times) are pre-sampled into a `Scenario`. | Common random numbers across policies: P0/P1/P2 see exactly the same world for each seed. |
| D004 | 2026-11-26 | No exposure feedback: a grounded aircraft's schedule still accrues exposure (protection flying is assumed), and lost flying is costed through the AOG penalty. | Keeps demand exogenous for paired evaluation. Disclosed in LIMITATIONS. |
| D005 | 2026-11-26 | Part master publishes a *vendor-quoted* MTBUR (true × lognormal noise, 25% optimistic on average). True MTBUR lives only in `data/ground_truth/`. | Realistic (quoted reliability ≠ in-service reality), and it gives the reliability-exposure model something real to beat. |
| D006 | 2026-11-26 | Material requests record **unconstrained** demand (removals happen whether or not stock exists). | Forecasting sees true demand rather than censored sales, which is how removal-driven demand works in aviation. |
| D007 | 2026-11-26 | The history (weeks 0–103) is generated by running the engine under P0 "legacy" rules on `history_seed`. | Gives realistic ERP-style tables (POs, ROs, transfers, AOG) that the planner screens can show. |
| D008 | 2026-11-26 | Holdout = 52-week horizon on seeds 1000–1019 (policies) plus the history seed's continuation (forecasting). Both are run once, after the freeze hash. | The brief's holdout discipline. |
| D009 | 2026-11-26 | Requirement deadline classes D0/D3/D10 are labelled hypothetical and never called MEL categories. | Integrity rule. Real MEL relief is operator-specific. |
| DOC-1 | 2026-11-26 | Result numbers in prose docs are written as `{{RESULT:<dotted.key>}}` placeholders. Keys name the output they come from (for example `policies.P2.aog_hours`, `frontier.recommended.capital_aed`). The full list is in `docs/agent_notes/docs-scaffold.md`. | No fabricated numbers. One grep (`grep -rn "{{RESULT:" *.md`) shows what is still unfilled before release. |
| DOC-2 | 2026-11-26 | `data/data_dictionary.md` and `docs/assumption_register.md` are generated by `scripts/render_data_dictionary.py` from `schemas.py` and `assumptions.yaml`, never edited by hand. | The docs cannot drift from the contract. |
| DOC-3 | 2026-11-26 | Docs use two availability terms: P(X ≤ S) = "ready rate" (no backorder at a random moment) and P(X < S) = fill rate (an arriving Poisson demand finds stock). | The brief writes "availability P(X<S)"; both appear in the literature, so both are named explicitly to avoid an off-by-one in interviews. |
| FC-1 | 2026-11-26 | Syntetos–Boylan classes on weekly buckets of the training window (weeks 0–77) only. ADI = mean gap between successive non-zero weeks (the gap before the first demand is left-censored and not counted); CV² uses population std of non-zero sizes; < 3 non-zero weeks → `insufficient_data`. ABC by annual usage value (training mean × 52 × unit cost), A while the cumulative share above the part is < 80 %, B < 95 %, else C. | The thresholds and buckets are fixed before any selection-window data is seen, so the classes cannot leak. With fewer than 2 observed intervals, ADI and CV² are noise. |
| FC-2 | 2026-11-26 | Smoothing parameters (Croston/SBA/TSB grid {0.05…0.3}), MA window and bootstrap transitions are fitted per origin on data before the origin only. MASE scale = in-sample lag-1 naive MAE on the same data; a zero scale gives NaN and the flag `undefined`, never inf. | Hyndman & Koehler (2006) scaling, made explicit; a leak test perturbs the future and asserts identical forecasts and parameters. |
| FC-3 | 2026-11-26 | Champion per demand_class × part_class = lowest mean MASE over parts (part = mean over the 6 selection origins 78…98, h = 4), ties within 0.001 broken by smallest abs(mean bias), then simpler method. Cells with < 5 parts with defined MASE fall back to the pooled demand_class, then to the global pool. Evaluation weeks are never read. | Selection discipline; small cells would otherwise pick a champion on 1–2 parts. |
| FC-4 | 2026-11-26 | The `zero` forecast is scored as a benchmark but is not eligible as champion. | On intermittent series, MAE-type metrics (MASE included) reward an all-zero forecast, which implies holding no stock. On Car Parts, `zero` has the lowest mean MASE (see docs/agent_notes/forecasting.md), so the exclusion is a choice made openly, not hidden. |
| FC-5 | 2026-11-26 | Reliability-exposure prior: gamma(k, k·MTBUR_quoted), default k = 2 pseudo-removals. Future exposure is the planned flying programme (input). | The vendor quote is optimistic (D005), so a weak prior lets about 2 years of removals dominate while stabilising parts with very few removals. |
| FC-6 | 2026-11-26 | Willemain bootstrap jitter uses nearest-integer rounding (J = round(X + Z√X), J < 1 → X) instead of the original 1 + INT(·). | The original form adds about +0.5 units per demand on average. |
| SIM-1 | 2026-11-26 | Flight schedule and A-check kit plan are world-level (depend on `world_seed` only); scenario seeds vary only demand and common random numbers. Demand streams are one `SeedSequence([salt, seed, departure_week])` per week, ids are encoded by need-week (`removal_id = week·10⁴ + rank`, `request_id = week·10⁵ + rank`). | A planned schedule is not random across seeds. Per-week streams make a weeks 104–155 scenario identical to the same slice of a longer range without generating anything earlier (tested). |
| SIM-2 | 2026-11-26 | Flight hours come from great-circle distance × 1.05 / airborne speed (830 km/h NB, 870 km/h WB); turnaround is set so each tail hits its planned FH/day. FC/day follows geography: NB ≈ 4.2 (config 4.2), WB ≈ 2.4 (config 1.6), because the AUH–LHR/FRA/BOM/SIN mix averages ~5.6 FH per leg, not 8.75. `aircraft_master.fc_per_day_mean` is the geometry-consistent value. | Can't match both the WB FH and FC means with the configured routes. FH (the main reliability driver) is matched and the FC gap is disclosed. |
| SIM-3 | 2026-11-26 | NB overdispersion is a fleet-wide gamma frailty per (PN, week): weekly fleet counts are NB with var = μ + μ²/k. | Per-leg NB draws would average the overdispersion away, and forecasting works on weekly buckets. |
| SIM-4 | 2026-11-26 | Shop `capacity_slots` are bench/test-stand positions. A unit holds a slot for `engine.shop_bench_time_share` (0.05) of its work time; the rest of the work time runs outside the slot. | Taken literally, 14 slots at 15–90-day TAT can process fewer than 200 repairs a year against about 1,100 rotable removals. 0.05 was chosen on the first P0 history (about 0.8 bench utilisation at AUH_INHOUSE). On the calibrated history it gives about 0.68 at AUH and 0.30 at EU_VENDOR. |
| SIM-5 | 2026-11-26 | Expedite POs: lead = min(0.5 × drawn lead, cap by class {C: 2, E: 3, R: 5} days) at a 15% premium. They are raised at once for D0 backorders and just in time for D3/D10 (deadline − expedite time − 24 h). Each is netted against open expedite POs and repair returns already in work that are due back within the expedite time. | Without caps and netting, P0 histories showed ~50k AOG h/yr and runaway emergency buying. These are AOG-desk distributor and surplus-market buys, documented as ASSUMED. |
| SIM-6 | 2026-11-26 | Backorders are served most urgent first (earliest need_h + deadline). Kit reservations protect stock except against needs already AOG (D0 at need time, D3/D10 after their deadline), which may rob a kit. A D10 need shipped from stock goes by routine transport, because the deadline exceeds the routine mean + 2 sd; D0/D3 needs go emergency. | This is how a materials controller allocates. Strict FIFO with hard reservations had D0 requests waiting days behind kit claims that were three weeks out. |
| SIM-7 | 2026-11-26 | Outstation stock-transfer orders (STO) on AUH: the outstation IP includes pending STOs. When an AUH unit is shipped earmarked to an outstation backorder, an equal pending STO is cancelled. | Stops the backorder from being double-covered (STO + emergency shipment), which would leave the outstation above target. |
| SIM-8 | 2026-11-26 | P0 'legacy' rule (lead decision). Rotables: network float = ceil(quoted annual removals × quoted shop TAT / 365), with no transport, queueing or safety stock, all at AUH except 1 unit (taken from the float) at an outstation when the PN is D0 and quoted annual removals there are ≥ 4. C/E: min = 6 weeks of quoted demand, max = 2 × min at every station with demand (AUH sized on network demand), no deadline differentiation. Quoted demand = quoted MTBUR (C: quoted FC per unit) × planned utilisation × 50/50 hub/route split + expected A-check kit demand (`gnm.sim.quoted`). | Mediocre, not absurd. Public and planning data only, never removal history. |
| SIM-9 | 2026-11-26 | `inventory_transactions.qty_delta` tracks serviceable on-hand only. `UNSERVICEABLE_IN` and `CONDEMN` rows carry qty_delta 0; U/S movements live in `serialised_components`. | Σ qty_delta per PN/station then equals serviceable on-hand at every snapshot (tested). |
| DS-1 | 2026-11-26 | The web app is vanilla HTML/CSS/ES modules with no build step. D3, Plot and topojson-client are vendored UMD builds loaded as deferred classic scripts (globals `d3`, `Plot`, `topojson`); app code is ES modules. | GitHub Pages serves `/docs` as-is. No bundler means nothing to break and nothing to install; UMD builds are the only single-file distributions of Plot. |
| DS-2 | 2026-11-26 | `docs/data/manifest.json` lists which real exports exist. `data.js` loads `data/<name>.json` if listed, otherwise `data/fixtures/<name>.json`, and shows the FIXTURE DATA chip when `meta.fixture` is true. | Avoids 404 noise in the console while still falling back cleanly. The exporter only has to rewrite the manifest. |
| DS-3 | 2026-11-26 | A derived tertiary text colour `--c-text-faint: #8A9BAD` is added in CSS; tokens.json values are unchanged. Slate (#6B7C8F) is used for non-text only. | Slate is 4.36:1 on midnight (fails AA for body text) but passes 3:1 for UI graphics. The derived colour is 6.56:1 on midnight. |
| DS-4 | 2026-11-26 | The plan-view aircraft has two presentations: the full drawing sheet (callouts, dimensions, title block) when its host is ≥ 1000 px wide, and a compact crop with numbered badges on the airframe below that, with names in an HTML legend. | Callout text at 12 px becomes illegible below ~0.7× scale. The compact crop keeps the drawing large and crisp at 390 px, and the HTML legend is accessible. |
| DS-5 | 2026-11-26 | All illustrations are generated by Node scripts in `docs/assets/svg/src/` (deterministic output, versioned SVGs). Geometry is archetypal (swept wing ~33°, span ≈ length, nacelles at ~⅓ semi-span), not traced from any OEM drawing. | Originality and reproducibility; the drawings can be regenerated and reviewed as code. |
| DS-6 | 2026-11-26 | Fixtures are generated by `docs/design/make_fixtures.mjs` with a seeded PRNG; KPI fixtures carry an optional `spark[]` array and `target` for the instrument tiles. | Deterministic layout data. `spark`/`target` are optional: tiles render without them, so the exporter may add them or not. |
| SIM-10 | 2026-11-26 | Runs start in approximate steady state (lead decision). Each rotable's repair pipeline is seeded with round(quoted removal rate × quoted pipeline days) units in REMOVED/IN_REPAIR, with remaining times from the Scenario `pipeline` CRN. C/E on-hand starts spread over (s, S] from the `initial` CRN. Warm-up is 26 weeks (runs start at week 78). | Removes the empty-pipeline transient. Year 1 and year 2 of the history are now comparable (2,739 vs 2,768 AOG h on the central world). Uses only public quoted figures and is identical across policies. |
| SIM-11 | 2026-11-26 | Deferrable (D3/D10) R/E removals found at an outstation are rectified at AUH on the tail's next hub arrival with probability `generator.deferred_to_hub_share` = 0.92. D0 removals stay at the outstation. | Hub-and-spoke practice: deferred defects go back to base, which is hours away. Without this, rotable fill was capped near 0.6 under any hub-centric float. This is a calibration lever (SIM-CAL). |
| SIM-12 | 2026-11-26 | PS1 = GN-32-R014 'Carbon brake assembly', ATA 32, D0, FC-driven, qty 4 on both archetypes. True MTBUR 4,200 FC against a quoted 10,500 (2.5×). True TAT 20 d against a quoted 90 d, so the AUH float covers hub demand. P0 sees 2.8 quoted removals/yr at BOM (< 4) and holds 0 there. True BOM removals ≈ 8/yr. | Matches the design fixtures. BOM AOG for PS1 (144 h in history) is the largest outstation rotable driver. It is not the largest overall: AUH stock-out drivers such as GN-34-R012 (379 h) are bigger. Making it the largest would need a quoted optimism above 2.5× or a BOM rate above 10/yr, which breaks the P0 threshold. |
| SIM-13 | 2026-11-26 | `fleet.widebody.fc_per_day.mean` set to 2.4 to match the generated schedule (realised 2.44). FH unchanged. | Route geography gives about 5.6 FH per widebody leg (SIM-2). |
| SIM-CAL | 2026-11-26 | Calibration bands (ASSUMED, `calibration_targets`) for the P0 history of the central world: overall immediate fill 0.93–0.97, rotable fill 0.80–0.88, material AOG 1,500–3,500 h/yr fleet-wide, events 60–250/yr. Sensitivity variants scale only the TRUE MTBUR of R/E (`generator.variants`): low_stress ×1.90, high_stress ×0.85; quoted data and P0 are unchanged. Generator changes made to land in the band: deadline-class mix (R D0 0.45→0.10, E 0.25→0.08, C 0.05→0.02), deadline alt prob 0.10→0.05, mtbur_fh lower bound 3,000→4,000, mtbur_fc lower bound 2,000→2,500, deferred_to_hub_share 0.92. Achieved (history, weeks 0–103): central fill 0.958 / rotable 0.832 / 2,754 AOG h/yr / 90 events/yr; low_stress 0.970 / 0.881 / 1,817 / 57; high_stress 0.946 / 0.830 / 3,506 / 105. The calibration used P0 only (history + 5 selection seeds) and was locked in `outputs/freeze/calibration_lock.json` (config + src/gnm/sim/*.py + summary) before any P1/P2 policy existed. `tests/test_calibration_lock.py` enforces the lock. | A plausibility band for a 40-aircraft hub carrier on static legacy rules: mediocre but not broken, leaving realistic headroom for data-driven policies. Locking before any policy comparison stops the simulator being tuned toward a desired policy result. Re-lock only for documented non-calibration fixes. |
