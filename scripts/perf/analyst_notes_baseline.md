- **Firefox not run — local launch failure.** Playwright Firefox (build 1572) exits with "Could not find profile folder" on this macOS build, in and out of the sandbox (decision V21-FF). The matrix covers Chromium + WebKit only; Firefox cells are skipped, not passed.
- **Snapshot.** Five page agents were editing their views while the baseline ran. Cells whose first pass had click/intercept timeouts were run again after the lead's audit_lib fixes (it now closes the open drawer/modal or rail before each control, opens the rail at 390 px and scrolls each control to the centre). The rerun result replaces the first one.
- **CLS root cause (shell).** Every route has a layout shift of about 0.18 at 390 px and 0.10 at 1440 px. The source is `footer.disclaimer`. It paints inside the first viewport while `#view` is still empty, then the view renders and pushes it down. Lighthouse CLS (0.19 mobile / 0.095 desktop) is this same shift. Fix it in the shell: reserve a min-height on `#view` until the first render, or keep the footer hidden until `data-ready`. Owner: SHELL (index.html / app.js / base.css).
- **Lighthouse mobile Performance is pessimistic here.** The local server (Python http.server, standing in for GitHub Pages) does not gzip, and "Enable text compression" is the top opportunity, worth 2–6 s. GitHub Pages does gzip. Desktop scores are 90–93. The other mobile drags are unused JS and render-blocking CSS/fonts.
- **Harness caveats.** On lab/cutaway.html, clicking a part goes to another document (index.html#/parts?pn=…), and audit_lib then reports "Execution context was destroyed". The navigation is the intended effect, so these entries are harness artefacts. "focusable" entries are elements with `tabindex=0` that do nothing on Enter: either give them an action or remove the tab stop.
- **Keyboard.** Chromium only: macOS WebKit skips links on Tab unless an OS setting is on. Elements with role img/region (reading or scroll stops) are not required to react to Enter.
